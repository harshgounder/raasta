Zero-knowledge eligibility credentials: issuer signs a credential, holder proves one fact (over 18, state, income below limit) to a smart contract with a ZK proof, nothing else revealed. Circom or Noir, signature verified inside the circuit, browser proving.

## Mind-boggling demo angles (3)
- Private age gate: a demo issuer signs a date-of-birth credential, and the browser proves age ≥18 before a testnet contract unlocks access—without receiving the birth date. Build on StellarCred’s age circuit, replacing its server witness step with local execution for the strict privacy version.
- Means-tested grant without revealing salary: an issuer signs income, the browser proves income is below a public limit, and a contract releases a demonstration token. Adapt StellarCred’s upper-bound policy support and generate the witness locally; show that editing the signed income makes verification fail.
- Resident-only ballot: add a signed state-code attribute, then use the Noir browser starter to prove that it matches the ballot’s allowed state before Solidity opens voting. Show the contract receiving only the predicate proof and necessary public verification inputs; this requires a new state schema, not reuse of StellarCred’s country field.

## Risks (3)
- “Nothing else revealed” is too strong: StellarCred exposes verification activity and wallet-to-claim links, and its current witness endpoint introduces a server trust boundary. Public commitments, issuer identifiers, policy inputs, and transactions must be disclosed honestly in the demo’s privacy explanation.
- Proof validity is not the same as trustworthy eligibility. The contract must enforce the intended issuer, policy inputs, verification key, validity/revocation rules, and replay protections; a trusted issuer can still sign false attributes. Modified Galactica circuits also require a production phase-2 trusted setup.
- Live-demo reliability remains unbenchmarked: browser proving time and memory were not established in the reviewed evidence. Circuit artifacts and compiler/verifier-key versions must match, while Galactica additionally introduces extension installation and MetaMask Flask dependencies.

## Missing pieces (3)
- For the closest match, StellarCred, replace POST /api/witness with browser-local witness execution before making an end-to-end holder-only privacy claim.
- Add a signed subnational-state schema and predicate. StellarCred’s documented jurisdiction encoding is an ISO country code, not a US-state credential.
- A polished, extension-free issuer → browser holder → smart-contract application covering all three requested predicates was not established among the reviewed projects. The Noir starter needs credential-specific integration, while the Privado example repository needs a browser frontend.
