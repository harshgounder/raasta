## Mind-boggling demo angles (3)
- Database detective: ask a plain-English question over a messy database and watch the browser reveal schema inspection, generated joins, execution results, and proposed consistency checks before showing a chart. Use Vanna's frontend with a local XiYanSQL-7B backend, clearly displaying SQL and validation evidence.
- The analyst that refuses to bluff: include questions requiring missing fields or undefined business rules, then show an explicit cannot-answer response and a clarification request instead of fabricated numbers. Run this through the browser UI with custom answerability gates on the local backend; this refusal behavior must be implemented and evaluated.
- Airplane-mode analyst: after downloading the 1.12GB Qwen coder model and application assets, disconnect the network and answer questions entirely in the browser using wllama plus a browser-side SQLite engine. Show local SQL execution and a scorecard on selected original BIRD Mini-Dev examples; this is a proposed integration, not evidence that the small model matches XiYan's BIRD score.

## Risks (3)
- Performance and portability: model download size is not total runtime memory. CPU inference may be slow, and wllama documents a 2GB per-file limit; larger models need splitting and sufficient browser memory. The 1.5B browser fallback has no verified BIRD score here.
- False confidence and misleading scoring: executable SQL can still use incorrect joins, filters, or business definitions. XiYan's reported BIRD development scores are standalone model results, not scores for the proposed validated/refusing agent; report the final system's execution accuracy and abstention performance separately.
- Execution safety and reuse terms: use read-only database access, bounded execution, and sandboxing rather than trusting generated SQL or code. Preserve BIRD's CC-BY-SA-4.0 obligations and applicable database-source terms when redistributing demonstration data.

## Missing pieces (4)
- No examined project was verified to provide the complete combination of browser demo, exclusively <=8B models, SQL execution, semantic result validation, reliable abstention, and a published BIRD score.
- A validation-and-abstention layer: schema/field availability checks, ambiguity handling, result sanity checks, bounded repair attempts, and a dedicated unanswerable-question evaluation set. Successful execution alone is not semantic validation.
- A reproducible final-system BIRD harness recording model revision, quantization, prompts, schema format, evidence use, execution accuracy, latency, and refusals. Start with the original 500-example Mini-Dev subset, but do not label its score as full BIRD development or test performance.
- For browser-only execution, integration of wllama, browser-side SQL execution, database loading, caching, and memory management remains custom work; the shortlisted application frameworks normally use a backend.
