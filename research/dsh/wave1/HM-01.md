## Mind-boggling demo angles (3)
- Proposed molecule X-ray: paste a batch of SMILES and watch the browser draw structures beside separate parse failures, valence findings and unspecified-stereochemistry warnings. RDKit.js handles local rendering and descriptors; detailed Python diagnostics use a pinned CPU service until equivalent browser functionality is verified.
- Proposed identity switchboard: compare the original salt, an explicitly selected parent and alternative tautomer forms, with property changes and every transformation shown side by side in the browser. ChEMBL parent extraction can run behind the UI; tautomer enumeration and its audit trail remain implementation work, and the original input is never overwritten.
- Proposed offline time machine: export a run capsule, disconnect, then import it into a browser that verifies the bundled engine and dataset hashes before replaying descriptor calculations on a small frozen subset. The UI flags changed outputs and preserves unavailable properties as null with reasons, rather than silently fetching or inventing replacements.

## Risks (3)
- Chemical interpretation: successful parsing is not evidence of fully specified stereochemistry or the intended chemical identity. Sanitization bypasses, salt removal and tautomer choices must not be presented as harmless repairs; preserve the original and require explicit transformation policies.
- Execution and replay: RDKit.js exposes only a subset of RDKit, so advanced Python workflows cannot be assumed to run unchanged in-browser. Large data distributions are unsuitable as browser payloads; exact replay requires pinned artifacts, retained data and tested serialization, while a server fallback introduces upload/privacy considerations.
- Data rights and snapshot integrity: ChEMBL requires CC-BY-SA-3.0 compliance and attribution including its release version. PubChem licensing varies by contributor, and its documented monthly RDF refresh is not an immutable archive; retain permitted source bytes, provenance metadata and hashes rather than depending on a moving download URL.

## Missing pieces (4)
- A unified browser UI and typed result contract are still needed: distinguish parse errors, chemical warnings, unavailable source values and calculation failures. Keep missing values null with reasons, and separate computed descriptors from experimental or predicted properties; the deterministic core needs no learned model weights.
- Browser/Python validation parity remains unestablished. Add and test detailed valence diagnostics, potential-but-unspecified stereochemistry detection, salt/mixture handling and an explicit tautomer policy without assuming these are all exposed by RDKit.js.
- A content-addressed replay capsule is not established by the reviewed projects: retain original inputs, engine/WASM or container artifacts, dependency versions, transformation options, descriptor definitions, dataset bytes, provenance, hashes and stable output serialization.
- The frozen data layer still needs assembly. Select a small ChEMBL 37 subset and retain a separately identified PubChem subset with contributor licensing and acquisition metadata; a verified immutable PubChem snapshot endpoint and a ready-made adversarial validation suite covering the requested edge cases were not established.
