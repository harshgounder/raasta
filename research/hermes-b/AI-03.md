### The Four Acceptance Tests That Matter

| Requirement | Observable acceptance test | Failure that must not be disguised |
|---|---|---|
| Extraction accuracy | Each displayed relationship opens its supporting passage; allow correction or rejection | A plausible relationship is treated as a documented fact |
| Community quality | Themes have readable labels and can reveal their member entities/documents | A giant unlabeled cluster is called a meaningful topic |
| Routing | Show Local / Themes / Both and the evidence actually selected | A mode label changes while the retrieval behavior does not |
| Path transparency | The displayed edges carry evidence IDs used by that answer | A shortest path is invented after generation and presented as the model's reasoning |
| Two-store compliance | Show a graph-DB record and a vector-DB record from the same ingestion | NetworkX plus a JSON file is quietly described as two databases |
| Citation grounding | Clicking a claim opens the corresponding document passage/page | A document-level link is presented as proof of every sentence |

These are proposed product acceptance tests, not features attributed to every candidate. The distinction is important: LightRAG lists retrieval modes, while Neo4j builder documents response-source metadata; neither statement alone establishes sentence-to-edge replay. Confidence: High. Three tensions determine the winner. First, **the strongest thematic pipeline is not necessarily the fastest polished website**: Microsoft's community structure and Neo4j builder's interface solve different parts of the statement. Second, **the most visually impressive graph can be the least honest explanation** if it is not the evidence actually retrieved. Third, **supporting local models is not proof of fitting this laptop**, and supporting providers is not proof that inference is free.

The non-obvious opportunity is to make limitations part of the product interaction. Show conflicting sources, preserve uncertain identity matches, reveal routing, and abstain when support is missing. That creates an understandable evidence tool instead of an attractive but unverifiable answer machine.

**Final recommendation:** choose **LightRAG-first**, with a quick switch to **Neo4j-builder-first** if its stock application is easier to launch. Build one selected evidence graph, one source drawer, one contradiction fixture and one honest fallback. Do not claim full AI-03 completion until the separate databases, actual communities, route behavior and answer-linked evidence IDs are all demonstrated.
